# Free English voice path for LYA — 2026-10-03

Owner reports weak/poorly understood microphone sound even close to the mouth, especially longer and slower questions. Requested GitHub/internet research and a professional solution; clarified English and no ongoing cost. This is a researched recommendation, not a tested replacement or a claim that the failed live gate is resolved.

## Recommendation

Use an entirely local path: verify the selected input and its intelligibility; benchmark an independent English recognizer; pilot streaming English Zipformer through sherpa-onnx; compare gentle noise suppression with raw input; then integrate only a candidate that passes the owner clock/long-question/interruption gates. Existing voice output can remain warm while input is improved. No paid cloud service is needed for this proposed path.

1. **Free independent control: Windows Voice Access, English–India.** It supports offline dictation after an initial language-model download on supported Windows 11 versions. Open Start -> Voice access, select English–India, and use an unsaved scratch text field to compare a full slow question with the same input. If it succeeds while LYA fails, that narrows the fault to LYA capture/recognition/turn handling. If both fail, input quality remains a leading hypothesis; it still does not prove a defective microphone. Voice Access is an independent test or dictation fallback, not an embedded LYA API or an already-connected hands-free integration. [Microsoft setup documentation](https://support.microsoft.com/en-us/accessibility/windows/voice-access/set-up-voice-access).
2. **LYA engine candidate: sherpa-onnx, streaming English Zipformer.** Maintainers document local Windows/Python support and English streaming models with CPU/int8 inference. A concrete initial candidate is sherpa-onnx-streaming-zipformer-en-2023-06-26 using its int8 encoder/joiner. Pilot it outside production with public fixtures first, then owner-authorized in-memory input. Its architecture fits continuous partial transcripts and adjustable endpoints; accuracy on this owner and laptop is untested. Do not infer better accent accuracy from the model name or published benchmarks. [Maintainer repository](https://github.com/k2-fsa/sherpa-onnx), [English model instructions](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-transducer/zipformer-transducer-models.html#csukuangfj-sherpa-onnx-streaming-zipformer-en-2023-06-26-english).
3. **Optional noise reduction: RNNoise.** The Xiph library is designed for real-time speech enhancement. Werman provides Windows plugin instructions with Equalizer APO, but explicitly warns that weak/poor microphone speech can be mistaken for noise. Compare raw/filtered recognition first, avoiding an aggressive gate for soft speech. The documented plugin expects 48 kHz; current LYA capture is 16 kHz, so direct insertion without proper resampling is incorrect. A system-wide plugin also requires installation/device configuration and is not automatically part of LYA. No plugin, driver or filter was installed. [Xiph RNNoise](https://github.com/xiph/rnnoise), [Werman instructions and limitations](https://github.com/werman/noise-suppression-for-voice).

## Required LYA behavior in a candidate pilot

These are proposed changes, not implemented by this research task:

- Keep one input stream open through a conversation, rather than repeatedly switching microphone/playback modes.
- Display partial recognized words while listening, accumulating a complete turn before submitting it.
- Begin slow-speech tuning with approximately 2.5–3 seconds of speech-free pause, then measure premature submissions and response delay. This is a trial setting, not an established optimum. Raise the bounded long-turn limit from 30 seconds only with explicit incomplete-turn handling; never forward a fragment at the limit.
- Pause output promptly on detected new speech, then recognize whether it is stop/cancel or a follow-up. Compare against false interruptions from background people and speaker echo; headphones may help acoustic separation. Do not claim owner-only speech detection.
- Retain uncertain-input repeat behavior and the existing manual stop control. Test long questions with internal pauses, soft normal speech, non-speech noise, competing voices, and stop during a reply separately.
- Local recognition is command input, not identity verification. Protected actions must retain their existing authentication/approval requirements. No enrollment or new biometric speaker identification is proposed.

## Input and hardware findings

LYA currently chooses Windows' default WASAPI input, with PortAudio default as fallback. It does not pin an owner-chosen microphone. Selecting the correct input explicitly is therefore part of the next investigation. A close microphone does not prove the selected Windows input is that physical microphone.

Bluetooth Classic switches to the hands-free profile when its microphone opens, with 8/16 kHz speech modes and concurrent mono playback. This could explain degraded capture/playback if the active headset uses that profile; the actual codec/profile was not measured here. LE Audio behaves differently. The proposed A/B control is an existing wired USB/analogue microphone, if available, against the current path using the same phrases. [Microsoft Bluetooth documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-classic-audio).

No purchase is required for the software pilot. If a purchase is later acceptable, shortlist a wired boom microphone headset connected to USB: Logitech H390 as a basic option, Jabra Evolve2 50 as a professional option. Both manufacturers describe noise-reducing microphones; neither establishes guaranteed owner recognition in crowds. Prices, seller authenticity, connector choice, return policy and personal comfort need checking after a budget is supplied. Earphone ANC and microphone noise suppression are separate features. [Logitech India product page](https://www.logitech.com/en-in/shop/p/h390-usb-headset.981-000485), [Jabra official specification](https://www.jabra.com/_/media/Jabra_VXi_Product-Documentation/Jabra-Evolve2-50/Technical-specifications/RevB/EN-JabraEvolve2-50-Tech_spec_v17022025.pdf).

## Other candidates considered

- Larger faster-whisper models remain possible local comparisons. Existing Whisper base previously hallucinated on the failed input; that does not prove every Whisper model fails. Larger models still need host-specific accuracy/latency/memory measurements before recommendation. [Maintainer documentation](https://github.com/SYSTRAN/faster-whisper).
- OpenAI Realtime semantic VAD can accommodate slower turns and provides interruption handling; Deepgram Flux also documents configurable turn detection. These are online services and no perpetual zero-cost allowance was established, so they are outside the owner's chosen free local path. No API key was read and no audio was transmitted. [Official OpenAI VAD documentation](https://developers.openai.com/api/docs/guides/realtime-vad), [Deepgram turn settings](https://developers.deepgram.com/docs/flux/configuration).
- NVIDIA Broadcast was considered, but compatible GPU requirements prevent treating it as a universal free laptop solution. No package was installed. [Manufacturer page](https://www.nvidia.com/en-us/geforce/broadcasting/broadcast-app/).
- AudioRelay documents an Android phone-to-Windows microphone over USB tethering, but its free-tier restrictions/privacy were not established sufficiently for a primary recommendation. No app or virtual driver was installed. [Vendor instructions](https://audiorelay.net/docs/windows/use-your-phone-as-a-mic-for-windows).
