## Implemented boundary

[memory_b2_credential.py](../../brain/memory_b2_credential.py) provides an explicit Windows owner-terminal command plus a protected handoff to the existing fake-data backup worker. It uses already-installed pywin32/Windows DPAPI directly, with user-scoped protection and UI forbidden; it never imports or accesses the existing `security.vault` key. No new dependency, system setting or scheduled job is added.

Before any network request, provisioning requires exact fake-data approval, an existing unlinked parent folder/new output path and a successful DPAPI roundtrip. The issuer ID/secret are entered using hidden local prompts, without secret command-line arguments. The command refuses redirected input and getpass fallback. It prints the selected bucket, literal `lya-memory-lab/worker/` prefix, exact `listBuckets`/`readFiles`/`writeFiles` permissions and 3,600-second duration, and requires the owner's explicit confirmation before credential entry/network use. This is an access-creation command, not a browser-login check.

The issuer authenticates through the worker's existing bounded HTTPS transport. Its required privileges and the exact existing private bucket are checked before one `b2_create_key` request. The request uses the v4 `bucketIds` field and a one-hour expiry. The response must match the request. The child then authenticates independently through the existing worker checks, and its actual expiry must match the create response. The local one-hour check allows 60 seconds of clock skew and requires at least a minute remaining. Five HTTPS calls are expected for successful provisioning; none upload/download objects.

Only the child credential, exact scope and expiry are serialized; the issuer and its authorization token are never written. DPAPI ciphertext is checked before same-volume atomic create through the existing no-overwrite publisher. Existing/racing outputs survive. Loading bounds the file, rejects tampering/schema/scope/expiry mismatches, and has no plaintext or non-Windows fallback. `backup_with_credential()` checks approval before reading the protected file and gives only the child to the existing worker. Fresh `RecoveryPins` and observation remain separately required; no capsule unlock key is accepted.

The only change to [memory_b2_backup.py](../../brain/memory_b2_backup.py) is returning its already-validated expiry from `_B2.authorize()` to the new caller. Existing callers ignore that return. The [manifest](source-manifest.json) records all 27 reviewed sources and preceding hashes; 24 of 25 preceding sources remain identical. The prior revision's [runner/evidence](../2026-10-17-memory-backup-worker/README.md) remain preserved; use this folder's runner for the extended source revision.

## Checks and remaining limits

[All 63 distinct Windows cases pass](windows-validation.json), with zero failures/errors/skips: 16 new credential checks and the preceding 47 selected worker/pack/custody/encrypted-store checks. [Log](windows-validation.txt), [explicit runner](check.py), [tests](../../test_memory_b2_credential.py). Real DPAPI encrypted fake credentials and a fresh child process loaded them. The restricted handoff completed a simulated upload without issuer/unlock access. Failure cases cover permission/scope/expiry mismatch, unsupported host, bad protection, damaged/oversized inputs, cancellation, uncertain create reply, failed publication, racing output and unsafe terminal input. Wrong-key SQLCipher diagnostics are expected in negative tests.

All B2 HTTPS is replaced at the connection boundary. This does not qualify native live TLS/authentication, actual provider permission denials, a live credential or remote recovery. The 2026-10-20 resume verified all reviewed sources and the runner still match that passing run, exercised `--help`, and checked documentation/source preservation in [static validation](static-validation.json). No repeat runtime suite or new Linux qualification was needed for the unchanged Windows-only source.

A committed create with a lost reply can leave an unrecorded live child. There is no automatic retry or remote deletion; an uncertainty message requires owner inspection or waiting for the requested one-hour expiry. An expired local file remains encrypted on disk; it is refused, not silently replaced or deleted. Expiry is not instant revocation of all previously issued provider tokens; live revocation/token semantics still need qualification. Do not reuse/rotate a pilot automatically.

DPAPI protects data at rest for the current Windows account, generally on this machine. It is not independently surviving key custody, protection against malware running as the unlocked user, secure RAM erasure or full process isolation. Python/OS buffers cannot be reliably zeroed; the inherited deadline is cooperative, and atomic publication lacks portable directory fsync/power-loss qualification. Do not use this Windows blob as a recovery copy for LYA's unlock key, or hand it directly to WSL/Oracle.
