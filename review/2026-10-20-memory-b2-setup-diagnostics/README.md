## Change

- `--check-only` performs local protection, existing-issuer authentication/permission and exact private-bucket checks, then returns before the create request. It makes no credential file and no upload. It skips the access-creation confirmation because it creates no access; hidden owner key entry and interactive-terminal checks remain required.

The original generic error text remains; no response fields are retained in that exception. Existing failure handlers still reject the request. Status and a constant stage identify a failed issuer-authentication request without claiming why it was rejected.
- Errors once creation may have started retain the preceding uncertainty/no-automatic-retry rule. Minimal child capabilities, one-hour duration, exact prefix/private bucket, verified HTTPS, DPAPI, fresh pins and no-overwrite behavior are unchanged.
