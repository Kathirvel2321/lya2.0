## Cutover and protocol

The new type opens only an existing fake authority and exact existing latest store, with explicit generated capsule/unlock/storage/recovery inputs and an existing publication directory. `bind_publication()` is a separate approved, single-lineage cutover from unwitnessed authority schema 2 to schema 5. It requires the exact previously confirmed latest pins and authenticated trust record, verifies capsule keys against the existing authority, stages/readbacks those exact artifacts and journals the binding. Multi-lineage cutover, simultaneous TLS/witness binding and re-enrollment are not implemented. Older authorities reject schema 5 instead of bypassing publication. This is not a migration of any actual user store.

Normal writes, reads through `handle`, writer acquisition and authority restore reuse inherited authorization, writer fencing, canonical snapshots and idempotency. The new transaction path:

1. Holds the canonical source writer transaction and checks its exact journaled publication head.
2. Commits an opaque operation reservation into the separate latest store **before** source mutation. The reservation contains only an operation ID and previous publication metadata. It deliberately is not an authenticated recovery head; both old and current recovery readers reject it. No old snapshot is returned during uncertainty.
3. Performs the inherited source operation and commits the source pointer and operation/target-pins journal together. Failure before this commit leaves the source unchanged, with a reservation still blocking recovery.
4. Reacquires the source writer lock, proves its committed target, stages the fixed three encrypted files plus separate encrypted trust record, and verifies exact pins/readback. Missing files can be created on retry; existing different files are never overwritten. A flat object-ID/writer-epoch directory avoids redundant long paths. The pack retains its eight-MiB bound and exact three-file layout.
5. Confirms the latest head and clears its reservation, then commits the source journal's idle/confirmed head. Only after these steps does the inherited operation return. `handle()` rechecks the fresh authenticated turn after publication and adds `publication_confirmed=True`. An expired/cancelled caller receives no success even if the source already committed.

The source lock closes the race where a reconciler might otherwise release a reservation before an in-flight source mutation. Its durable journal blocks another source operation during an unresolved committed transition. Exact operation/target checks refuse superseded completions. Authority restore publishes the revoked-writer epoch before returning its quarantine result. Writer tokens are generated only by the existing authority and are never stored in the publication journal or returned by reconciliation.

An invalid/revoked operation can leave a rollback reservation. Approved reconciliation uses the source writer lock to prove the unchanged canonical source, verifies its exact prior publication and safely releases that reservation. It does not assume that an exception means rollback.

## Recovery after interruption

`reconcile_publication(lineage, approved=True)` verifies source/capsule/journal state under the canonical writer lock. It confirms only the observed committed source, or the exact unchanged prior source after a proven rollback. It handles latest confirmation committed before the source journal's idle update. Its response is metadata only: anchor, writer epoch, `publication_confirmed`, synthetic flag. It does not re-execute a request, return private content, mint a grant or guess an old state when source/custody is missing.

A caller whose reply was lost can reconcile, then retry the same request ID with a fresh authenticated turn. Existing authority receipts return the prior result without a second mutation. A locally committed source change may exist despite an error/no success reply; pending state means uncertainty, not automatic rollback. A source-catalogue rollback cannot replace a newer surviving latest head. If the source is lost while its reservation remains uncertain, recovery refuses instead of silently falling back.

The old code-only recovery ZIP is not rebuilt. It rejects an in-flight opaque reservation, and after stable confirmation it restores the newly acknowledged encrypted records from the surviving latest store, pack, trust and separately supplied fake unlock. The source-loss test checks the corrected record, forgotten/expired tombstones and zero active bindings/jobs after deleting the owned generated source/catalogue/witness.

## Limits and next step

This is a new optional local synthetic mode. No desktop/mobile runtime, provider, account, real key, enrollment, live store, service, deployment or default is connected. The existing TLS/network witness coordinator is unchanged and is not combined with this binding. Publication-bound owner reactivation is explicitly refused until separately qualified; existing authority reactivation remains unchanged outside this new mode.

Source catalogue/publication metadata remain trusted plaintext fixtures on one physical laptop. Independent hosting/custody, whole-source-and-latest rollback protection, full authority/owner-catalogue survival, power-loss/directory-fsync guarantees, remote fencing and production resource quotas remain open. Cooperatively serialized local SQLite transactions are not a distributed service. Standalone record-only recovery remains quarantined; it cannot activate writers or resume actions.

Next qualify the acknowledged path's latest-state/custody on a genuinely separate failure domain, then the intended witness/authority cutover and owner recovery before real private integration. No external transfer or deployment is authorized or performed by this local implementation.
