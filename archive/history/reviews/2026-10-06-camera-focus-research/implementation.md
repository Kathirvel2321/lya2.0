# Camera focus and owner access — implemented 2026-10-06

The owner's approved scope is camera highlights, a sequential scene tour,
bounded device work and **a verified LYA owner session before camera access**.
Existing accepted hearing, speech models, speaking voice, ordinary interaction,
crystal/interface, launch and credential behavior were preserved.

## What is connected

`desktop/experience.py` routes camera requests to `desktop/camera_eyes.py`.
Its access callback uses the existing `Brain._authorize('camera_view', ...)`:
unexpired identified session, active protected identity record and matching
administrator role. Guest, friend, expired, revoked, changed-session and
unreadable-store access fail closed, including the camera button. The model's
response and the UI's role/color cannot grant access. `security/policy.py`
adds only the camera-view permission; existing private-action phone gates remain.

`vision/answers.py` now returns the answer, selected detection and bounded ordered
items together. Native Qt paints corner brackets and numbered name tabs using
the same selection that supplies the answer. Coordinates follow image scaling
and letterboxing. Multiple same-category named targets request clarification.
Existing 2D hand pointing selects a supported detected object; no arbitrary
object, depth or identity inference was added.

The selected image is explicitly a **checked frame**. The worker sends the
actual analyzed pixels once per result; the UI validates dimensions, counts,
labels, finite coordinates, confidence and timestamps before decoding/marking.
Batched newer preview packets retain matching checked pixels. A fresh question
requires analysis no older than two seconds; boxes never pretend to track a
moving object on unrelated new video. `Live view` resumes the current preview.

“What all can you see?” returns up to 12 distinct numbered detections, left to
right, then top to bottom. With speech enabled, the existing voice describes one
item at a time and marks it before playback; completion advances the queue.
Stop, new question, quiet/voice-off, access loss, close, sleep and playback failure
cancel further narration. Quiet mode shows the inventory without speaking.
The displayed inventory discloses the 12-item cap when reached.
Camera answer panels explicitly say `LOCAL CAMERA · NO IMAGE UPLOADS`,
independently of a preceding general cloud reply.

## Resource and privacy boundaries

- Existing local models only; no dependency/model download, image upload,
  remote camera endpoint, saved frame or video. Camera observations do not enter
  chat history/model context and are cleared from their answer panel at view end.
- One worker and one inference job at a time; preview capped at 15 FPS and
  analysis at 2 FPS, dimensions at 1280×720, at most 12 objects/two hands.
  Processing libraries use two threads; no accumulating inference queue.
- Explicit start only; existing 90-second worker-session limit retained.
  The parent checks access every second, stops/clears on revocation or session
  change, and renews a three-second worker lease. The worker also checks the
  owner's expiry and exits when the parent pipe closes or renewals stop.
  Camera release precedes inference-pool shutdown; native camera calls are
  not preemptible and the parent can terminate the worker.
- Close, hide, minimize, sleep, worker failure and expiry release/stop the view
  and clear in-memory pixels, detections and pending tour state.
- The child receives an allowlisted environment with no provider credentials.
  A Python audit hook denies network connect/bind/send/name lookup and child
  command launch. This is defense in depth, **not an OS-level malware sandbox**.
  It cannot prevent another application already running as the Windows user
  from independently using that user's permitted webcam.
- This authenticates the LYA **session**, not every nearby speaker. An already
  verified owner session may still receive nearby spoken requests. Speaker
  biometrics/enrollment were not introduced or changed.

### Measured local worker cost

[resource-check.json](resource-check.json), generated by
[check_resources.py](check_resources.py), measures ten seconds using the existing
upstream public hand fixture and a fake camera, with the actual local models and
network guard. No owner sensor/private frame/store/key was read.

| Measurement | Result |
|---|---:|
| Preview frames / completed analysis jobs | 150 / 19 |
| Analysis median / maximum | 170.38 / 243.95 ms |
| Model initialization | 191.64 ms |
| Worker working memory / peak | 110.94 / 126.13 MiB |
| CPU, normalized across logical machine capacity | 8.18% |
| CPU, relative to one logical core | 65.44% |
| Camera released | Yes |

These are worker-only, short simulated results. They exclude the full LYA UI,
microphone, speech playback, battery/thermals and prolonged live-room load;
they do not guarantee no device pressure.
