# Owner face and voice profile enrollment

Status: implemented and synthetic-tested on 2026-10-09. LYA has **not** enrolled the owner; the user chose to do the real-device check later.

## What LYA stores

After a signed phone passkey assertion and separate spoken consent, LYA temporarily captures three face samples and three voice samples in a short-lived local process. It discards raw frames and audio from memory after deriving embeddings. The encrypted SQLite store receives only six normalized embeddings, their fixed model identifiers, timestamps, and one generic consent audit event. The already-confirmed display name and public passkey are stored by the earlier phone ceremony. The phone's private key stays on the phone. LYA asks for no password, recovery secret, government ID, address, or birth date in this step. Cancel, expiry, poor capture, or an inconsistent profile clears pending vectors and commits nothing. Existing profiles cannot be overwritten through enrollment.

Before microphone capture, LYA pauses its normal listener, signals it to stop, and waits for its thread to end. The worker then uses LYA's selected microphone, captures locally with voice activity detection, and stops after speech ends or at its 20-second bound. While the worker is open, the parent renews a short process lease; hiding or closing registration, cancellation, timeout, parent exit, or expired phone proof kills it. The worker has no provider keys, blocks Python networking/child-process/file writes, and verifies the face and speaker model hashes before capture. These controls are defense in depth against bugs; they do not isolate the worker from malware or an administrator controlling the same Windows account.

LYA requires the phone passkey for admin access and still requests fresh phone approval for private actions. Face and voice matching is a local recognition feature and does not grant access. The models have not been qualified for deepfake, printed-photo, injected-camera, recorded-voice, or demographic error rates. NIST disallows voice comparison as an authenticator and calls for presentation-attack detection when face recognition is used for authentication; this implementation makes neither claim. See [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) and [Apple's Face ID security overview](https://support.apple.com/en-us/102381). The iPhone passkey proves its authenticator's user-verification step; WebAuthn UV does not prove that only Face ID (rather than an allowed device-passcode fallback) was used.

## Local components

- OpenCV YuNet detects one face; OpenCV SFace's 128-dimensional model creates a profile. The OpenCV Zoo README describes alignment and a research benchmark, which is not a spoof-resistance result: [SFace model card](https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface). The runtime hash-pins its quantized ONNX weights at `2b0e941e6f16cc048c20aee0c8e31f569118f65d702914540f7bfdc14048d78a`.
- Resemblyzer 0.1.4 creates a 256-dimensional speaker profile from speech processed with librosa and WebRTC VAD. Its own README cautions that voice imitation detection is imperfect: [Resemblyzer README](https://github.com/resemble-ai/Resemblyzer). The local installed encoder weights are hash-pinned by the worker.
- `.venv-owner` is separate from LYA's accepted `.venv-asr`/`.venv-ui` environments. It reuses the existing UI environment's CPU PyTorch, NumPy, SciPy, OpenCV and sounddevice packages; only the listed audio libraries were added. `requirements-owner.txt` lists the isolated worker's additional audio packages. Resemblyzer's old package metadata asks for a `typing` backport and source-built `webrtcvad`; its code runs on Python's built-in `typing` and the pinned Windows wheel that provides the `webrtcvad` module, so install it separately with `pip install --no-deps Resemblyzer==0.1.4`.
- The OpenCV model weights are local, hash-checked and ignored by Git. Fetch a replacement only from the model publisher's [quantized SFace asset](https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface). The required SHA256 is in `security/owner_capture.py`; a missing or different file fails closed.

## Checks and limits

`validation.json` records 85 passing fake-key, temporary-store, synthetic-device, passkey, privacy, storage and existing-registration regressions. One Windows loopback HTTP test hit a host-side connection abort on its first full batch and passed its isolated retry in `http-retry.json`. The owner-profile tests include no real samples. `model-check.json` runs the real CPU models against OpenCV's public Lena fixture and LYA's existing synthetic Piper greeting; it verifies output dimensions and cleanup, not owner recognition accuracy. Loading both models took about 8 seconds, with 436 MiB working memory (441 MiB peak) and about 96% of one CPU core in this short test. The worker loads only after consent and exits after enrollment; full-app resource impact and sustained thermal behavior remain unmeasured. `worker-bridge.json` checks normal cancellation and parent-lease loss before any capture command. Resemblyzer's upstream package metadata also makes `pip check` warn about its legacy `typing`/`webrtcvad` dependency labels; the installed Python and pinned Windows WebRTC wheel provide the imports used by the worker.

The current profile store is encrypted using LYA's existing Fernet store and Windows DPAPI key. New profile writes protect the runtime data directory with the current Windows user and SYSTEM ACLs. Encryption and the ACL protect files at rest from other ordinary Windows accounts. A process running as the same logged-in user, Windows administrator, compromised host, or compromised passkey device remains outside that boundary; DPAPI and this laptop are not an independent recovery copy.

The owner should now use the usual launcher after fully quitting the existing LYA instance, say “register admin,” verify the iPhone passkey, and follow LYA's separate consent, camera and microphone steps. At the final review say “save my profiles.” The first live test must check natural voice/face capture, microphone selection, actual phone prompt, and listener stop/resume. If the owner cancels after phone verification, the phone credential remains registered but no face or voice profiles are saved; signing in again resumes the profile step. Do not reset it or the protected store.
