# One-shot local vision — 2026-09-23

LYA now has an opt-in `open vision` / `look around` / `scan room` window. It starts camera-off. Selecting **Scan once** launches a bounded child process, captures up to three camera frames at 640×480, analyzes the latest frame locally, and releases the device. The UI kills the child after eight seconds and on close. The image crosses only the local process pipe, is displayed in memory and is cleared on close. No file, cloud request, enrollment or identity template is created. No live camera was used during development or tests.

Object labels come from OpenCV Zoo's [NanoDet](https://github.com/opencv/opencv_zoo/tree/main/models/object_detection_nanodet), and face presence from [YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet). Their binaries and pinned hashes are listed in [the model manifest](../../models/vision/README.md). A face box means a face was detected; LYA does not know the person's identity and grants no access. Objects are confidence-filtered and can be wrong or absent, particularly small/occluded objects. This is not open-ended visual reasoning or an always-on camera.

The window has a static reticle and corner framing, no idle animation or full-screen takeover. A synthetic offscreen preview is [here](preview-camera-off.png). It is a layout preview, not proof of live-camera appearance.

Checks: three sensor-free core tests passed (blank frame, bounded fake camera, guaranteed release on unavailable camera). On a temporary public OpenCV sample image, YuNet detected one face and NanoDet labeled one person. Eighteen isolated desktop experience checks passed, including camera-off launch; no sensor was opened by those tests. The 1.03 MB NanoDet model loaded and inferred on a synthetic 416×416 input in about 58 ms in one run on this laptop; that is not a production latency or battery benchmark.

Next: owner tests Scan once from the normal desktop and judges visual clarity and object accuracy in ordinary lighting. Then benchmark camera startup, load and battery, calibrate thresholds and only later build consented SFace enrollment and encrypted templates under the existing registration policy. No model result may authorize protected actions.

## Live local vision follow-up — 2026-09-23

The owner clarified that a still JPEG was not the requested experience. `open camera`, `look around`, and `scan room` now start an explicit live local session; `open vision` opens camera-off for review. The Vision window offers Start/Stop, overlays face/object boxes and accepts questions about the current view. A separate bounded worker keeps the existing NanoDet and YuNet models loaded. The preview is capped at six frames/s, analysis at two/s, with one inference in flight and no queued model jobs. The camera stops on button, close, error or the 90-second worker limit (95-second UI guard). No frame is written or uploaded. `Scan once` remains available.

Grounded answers cover person presence, supported COCO objects and approximate screen position. They explicitly avoid identity, intent and permission claims. Pen/pencil are **not supported** by this tiny model and LYA says so rather than inventing a location. A face box, head motion or any photo/video must never authorize protected actions; Windows Hello PIN remains the authority. Real presentation-attack detection, owner recognition, pen-class detection, room-scale multi-camera search and natural open-ended visual reasoning are **not implemented**. This is an observed-scene helper, not a burglar alarm. No enrollment occurred.

Checks: five isolated vision tests and 18 desktop experience tests passed. A five-second real camera run initially delivered 9 frames due to synchronous inference. After moving inference to one worker thread, a bounded real camera run delivered 15 frames about 0.17 seconds apart after startup; first frame appeared around 2.66 seconds in that run. The offscreen Qt handoff showed first frame in 4.75 seconds, then Stop ended the child and cleared the preview. Tests logged only counts/timing and no camera content. Startup time varied and battery/accuracy have not been validated. Evidence scripts: `review/2026-09-23-vision/live_smoke.py` and `live_ui_smoke.py` (both access the real camera and require deliberate use).

NIST documents photo and video replay as biometric presentation attacks; this is why the vision output is advisory, not authentication: https://www.nist.gov/system/files/documents/2020/09/03/10_ibpc-prez-fido-ssanden-v5.pdf and https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=956456 . Next: owner tests normal live UI and reports useful object categories; add a separately evaluated lightweight pen-capable detector only if measurements support it. Evaluate actual presentation-attack resistance before ever considering face-based access, while preserving Windows authority.

Main-command routing follow-up: clearly visual questions now open Vision and wait for current analysis. Five vision and 19 desktop checks pass. This is typed-command integration; speech-to-text is not yet connected.
